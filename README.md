## Лабораторна робота №3

Виконано доступні частини: прогноз CO₂ за Engine_Size, класифікацію output із heart.csv та оцінок відгуків Coursera. `ice_cream_selling_data.csv` і `powerconsumption.csv` відсутні в обох репозиторіях викладача на перевіреному коміті. За рішенням користувача очікуємо оригінальні файли; ці два пункти не виконані. Необов’язкову бонусну модель не реалізовано.

CO₂: порівняно поліноми степенів 1–3, обрано кубічну регресію за найменшою 5-fold CV RMSE на train. На відкладених 187 рядках: MAE 27,71 г/км, RMSE 36,98 г/км, R² 0,661. Різниця CV із лінійною моделлю невелика; вона не доводить стійкої переваги кубічної форми.

Heart: один точний повтор прибрано до поділу, числові ознаки масштабовано, коди категорій оброблено OneHotEncoder. Порівняно LogisticRegression, RidgeClassifier, SGDClassifier і параметри регуляризації через 5-fold CV на train. Обрано LogisticRegression з C=0.1. На 61 validation-рядку: accuracy 0,852, macro F1 0,850, ROC-AUC 0,893. Модель прогнозує мітку датасету; це не клінічна оцінка ймовірності інфаркту.

Тексти: оригінальний [Kaggle Coursera Reviews](https://www.kaggle.com/datasets/septa97/100k-courseras-course-reviews-dataset), 107 018 рядків. Після усунення порожніх, повторних і неоднозначно розмічених текстів — 96 548. Прогнозується Label 1–5 лише за Review, без Id. TF-IDF включено до Pipeline і навчено всередині фолдів. Порівняно MultinomialNB, SGD із log-loss та LinearSVC за 3-fold CV macro F1. Обрано SGD; на validation: accuracy 0,741, macro F1 0,415. Baseline найчастішого класу: accuracy 0,727, macro F1 0,168. Дисбаланс і помилки за класами показано в ноутбуці.

Поділ усюди 80/20 з random_state=42; для класифікації — стратифікований. Обрання моделей відбувається лише на train. Метрики, коефіцієнти, індекси поділу й передбачення — у `outputs/lab3/`, графіки — у `figures/lab3/`, походження й SHA-256 — у `resources/lab3_sources.json`. ## Лабораторна робота №2

Виконано п’ять пунктів: читання текстів із JSON, очищення та нормалізація, TF-IDF і косинусна схожість, теплова карта, аналіз окремого власного корпусу. У ноутбуці є умови, пояснення українською, виконані комірки та графіки.

Використано оригінальний [resources/data.json викладача](https://github.com/maxvonlancaster/ida-labs/blob/main/resources/data.json): об’єкт із полем `texts`, що містить 10 англомовних текстів про Oppenheimer, качок, теорію графів та один беззмістовний текст. Файл скопійовано без змін. Для пункту 5 підготовлено окремі вісім власних коротких англомовних текстів у `resources/lab2_own_texts.json`. Точне джерело, коміт і SHA-256 обох файлів — у `resources/lab2_sources.json`.

Використано PorterStemmer із NLTK, pyspellchecker та TfidfVectorizer зі scikit-learn. Конвеєр обробляє англійську мову: розкриває скорочення, прибирає пунктуацію, цифри та спеціальні символи, виправляє орфографію до стемінгу й прибирає стоп-слова зі збереженням заперечень. Фактичні виправлення записуються в журнал. Моделі ембедингів є необов’язковим доповненням умови; тут реалізовано TF-IDF.

Після встановлення спільних залежностей друга робота запускається без мережі та API-ключів:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe lab2.py
.\.venv\Scripts\python.exe execute_notebook.py assignement-2.ipynb
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

У Linux/macOS замініть `.\.venv\Scripts\python.exe` на `.venv/bin/python`.

Результати: `outputs/lab2/` — TF-IDF, IDF, матриці схожості, рейтинги пар і журнали обробки; `figures/lab2/` — дві теплові карти. Префікс `teacher_` позначає результати для 10 текстів викладача, `own_` — для власних текстів. На діагоналі матриці непорожніх документів — 1; матриця симетрична. Косинусна схожість TF-IDF оцінює спільну лексику, не є ймовірністю й не визначає зміст речень повністю. Порожній документ має нульовий вектор; повністю порожній корпус спричиняє зрозумілу помилку.

## Дані та результати

- `resources/weather.json`: чотири дні погоди Токіо у серпні 2024 року.
- `resources/weather.csv`: 6 812 спостережень за 1997–2015 роки. Місто у файлі не зазначено.
- [Wine_Quality.csv](data/kaggle/Wine_Quality.csv): 6 497 рядків, 13 колонок, 38 реальних пропусків. Завантажено з рекомендованого [Kaggle-набору](https://www.kaggle.com/datasets/ilayaraja07/data-cleaning-feature-imputation). У початковому прикладі студентів пропуски лише категоріальні, тому обрано числові дані вина з того самого архіву.
- [Походження і контрольна сума CSV](data/provenance.json).
- [Підсумок експерименту](outputs/summary.json), [похибки по ознаках](outputs/imputation_validation.csv), оброблені CSV у `outputs/`.
- [Джерела вебзапитів і час отримання](outputs/collection_sources.json).

У контрольному експерименті середня стандартизована MAE: KNN — 0.2760, median — 0.7046, mean — 0.7300, mode — 0.7438. Для підсумкового заповнення обрано KNN. У фінальному наборі пропусків немає. Оригінальні відомі значення збережено.

80% рядків використано для навчання, 20% — для валідації (`random_state=42`); у перевірочній копії приховано приблизно 10% відомих числових значень. Масштабування та заповнювачі для оцінювання навчаються лише на train. Це один експеримент, а не гарантія точності на справжніх пропусках. Випадковий поділ рядків може розмістити повторювані профілі в обох частинах; для оцінки узагальнення на нові профілі потрібен поділ за групами.

Основний скейлер — Robust через асиметрію та крайні значення. Порівняння з MinMax та Z-score є в ноутбуці. Ціль `quality` та категорія `type` не масштабуються і не беруть участі у відстанях KNN. Для подальшої прогнозної моделі перетворення потрібно навчати заново лише на її train-вибірці.

## Запуск

Перевірено з Python 3.12. Залежності зафіксовано у `requirements.txt`.

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe lab1.py --collect
.\.venv\Scripts\python.exe execute_notebook.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Linux/macOS:

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python lab1.py --collect
.venv/bin/python execute_notebook.py
.venv/bin/python -m unittest discover -s tests -v
```

`lab1.py` без `--collect` виконує аналіз локальних даних без вебзапитів, якщо CSV Kaggle на місці. `--collect` та виконання всього ноутбука потребують інтернету. Збережений ноутбук можна переглядати без запуску. Для інтерактивного редагування використайте VS Code з Jupyter або встановіть JupyterLab окремо.

`parse_json` і `parse_csv` повертають список словників. Якщо дати немає — порожній список; неправильна календарна дата спричиняє `ValueError`. Мережеві та HTTP-помилки не приховуються. Завантажувач Kaggle використовує публічний endpoint та локальний кеш замість `kagglehub`.
